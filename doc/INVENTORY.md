# 背包、倉庫與換裝預覽

背包及卡普拉倉庫將原生武器／頭部分類細分為單手武、雙手武及頭部上／中／下。武器下方另有單行、可橫向捲動的武器類型。分類在原生排序及分頁之前套用；不以隱藏當頁格子的方式代替全清單分類。

換裝候選列補齊內建／Tier 詞條、兩個主要屬性、副屬性與技能傷害，按實際精煉倍率顯示。原生穿裝、轉卡確認、保護與新裝備標記流程仍由遊戲執行。

## 卡片比較規則

- 候選裝備所有插槽皆空時，預覽沿用目前該欄位裝備的卡片，按原有順序放入。
- 候選總插槽較少時，只計入能容納的卡片，提示未計入數量；沒有插槽時提示無法計入卡片。
- 候選只要已有任何卡片（包含部分插槽仍空），完全使用候選原本的卡片，不補空槽。
- 右側 GS、差值及中間屬性比較使用相同的預覽；標示「同卡預覽」，並明確說明實際換裝仍需遊戲確認。
- 不實際插卡、不轉移卡片，不修改帳號物件或存檔。

## 原生對接與維護依據

- https://ro.hans-webgametw.com/build/soul_linker-DllBVIRO.hzf296bcc4.js

原生背包為 `#cp-inv-filters`／`#cp-inventory`，倉庫為 `#ks-filt`／`#ks-bag`／`#ks-st`，換裝候選與比較為 `#cp-eq-list`／`#cp-eq-current`／`#cp-eq-cmp`。

`src/inventory.js` 只在原生同步顯示回呼執行期間包裝 Array 的讀取方法，並在 finally 還原。分類只限制背包的顯示判定及倉庫的 passes 判定，不限制原始帳號或 ownership 陣列，避免誤改「取出這一頁／全部取出」等原生動作所捕捉的清單。

卡片預覽讓原生候選讀取取得同 uid、具有獨立 cards 陣列的複本。原生 GS 與原生角色數值比較繼續執行，因此包含職業評分、雙手武器移除盾牌與原生數值限制；沒有另寫一套 GS／角色屬性公式。原生真實點選先正常執行，以維持新裝備的標記保存；接著才重畫預覽。真正的「裝備」按鈕不包裝。

原生 GS 為裝備本身分數加各卡片分數，故相同職業／目前裝備下，同一插槽容量只需求一次原生卡片增量，再套到右側其他候選。原生清單重畫、切換角色或裝備欄位時會重算。原生重新指派 list/control 的回呼時也重新綁定，避免沿用舊角色的閉包。

詞條使用共用模組的實際裝備定義、`bs` Tier 詞條與 `bt` 隨機屬性轉換，精煉倍率對照原生 Go／vr；技能傷害依原生 rw 的方式乘精煉倍率。卡片並非裝備內建詞條，不將模擬卡片混入候選本身的詞條說明。

## 驗證

`tests/fixtures/inventory-native.json` 保存上述版本的原生比較、重畫及穿裝函式片段，供隔離測試執行。測試包括 GS／中間數值採同卡、空槽與部分插卡、容量不足／零插槽、雙手武器與盾牌、新裝備保存及重畫、例外還原、倉庫 60 件分頁前分類與原生批次範圍、精煉詞條及真實 MutationObserver 收斂。測試不等於完整遊戲或 iPhone Safari 實機驗證。
